# 吃了么设计规格

日期：2026-05-18

## 目标

“吃了么”是一个面向 iPhone 的健康饮食记录 PWA。首版目标是让用户在不固定餐次的真实饮食习惯下，快速记录“刚吃了什么”，并看到粗略的今日营养汇总和最近趋势。

首版坚持本地优先：不登录、不联网同步、不做 AI 诊断、不做拍照识别。所有营养结果都作为粗略估算展示，允许用户手动修正。

## 平台与安装

- 形态：iPhone Safari 可运行的 PWA。
- 安装：支持“添加到主屏幕”。
- 技术：纯前端 HTML、CSS、JavaScript。
- 存储：首版使用 `localStorage`；照片较多或数据规模变大时再迁移到 `IndexedDB`。
- 项目路径：`/Users/sen/projects/chileme`。

## 首版范围

包含：

- 今日饮食事件流记录。
- 常吃食物库。
- 包装食品标签录入。
- 个人份量和容器校准。
- 每条记录可附照片，照片只用于回忆和人工查看。
- 今日营养概览。
- 最近 7 天基础趋势。
- PWA manifest 和图标。

不包含：

- 拍照识别、拍照估重或图像算法计算。
- 账号登录和云同步。
- AI 菜单建议。
- 医疗建议、健康诊断或疾病管理。
- 大型通用食物数据库。

## 页面结构

### 今天

首页采用“快捷添加 + 今日时间线”的合并结构。

顶部展示今日概览：

- 热量。
- 蛋白质。
- 饮水。
- 可选目标进度。

中部是横向滚动的常吃食物快捷区：

- 常吃食物卡片左右滑动。
- 卡片展示食物图片、名称和默认份量。
- 点击卡片后弹出份量选择。
- 支持“搜索/更多”和“自定义记录”入口。

下部是纵向滚动的今日时间线：

- 不按早餐、午餐、晚餐分组。
- 正餐、零食、饮料都按实际时间追加。
- 每条记录展示时间、食物、份量、粗略热量和缩略图。
- 记录可编辑、删除、补充备注和照片。

### 食物库

用于维护用户自己的常吃食物和包装食品。

常规食物字段：

- 名称。
- 分类。
- 图片。
- 营养基准：每 100g 的热量、蛋白质、碳水、脂肪。
- 默认份量。
- 可选份量模板，例如 `1拳 = 150g`。

包装食品字段：

- 名称。
- 图片。
- 包装规格，例如 `1包 = 200g`。
- 营养基准：每 100g、每份或每包。
- 默认记录单位，例如 `1包`、`半包`、`30g`。

### 统计

首版展示最近 7 天趋势：

- 每日热量。
- 每日蛋白质。
- 每日饮水。
- 记录次数。

统计页面只提供事实型汇总，不做健康结论。

### 设置

设置页面包含：

- 每日目标：热量、蛋白质、饮水，可选填写。
- 个人尺度：拳头、掌心、手指宽度。
- 常用容器：碗、杯、勺。
- 数据管理：清空示例数据、导出 JSON、导入 JSON。

## 核心数据模型

### Food

```json
{
  "id": "food_rice",
  "name": "米饭",
  "category": "主食",
  "kind": "regular",
  "image": "data-url-or-generated-asset",
  "nutritionMode": "per100g",
  "nutrition": {
    "calories": 116,
    "protein": 2.6,
    "carbs": 25.9,
    "fat": 0.3
  },
  "defaultPortionId": "portion_rice_fist"
}
```

`kind` 可为：

- `regular`：常规食物。
- `packaged`：包装食品。

### Portion

```json
{
  "id": "portion_rice_fist",
  "foodId": "food_rice",
  "label": "1拳",
  "grams": 150
}
```

份量模板可以来自食物自身，也可以来自个人校准和常用容器。

### Calibration

```json
{
  "fistWidthCm": 8.5,
  "palmWidthCm": 8,
  "fingerWidthCm": 1.8,
  "containers": [
    {
      "id": "bowl_home",
      "label": "家用白碗",
      "capacityMl": 350
    }
  ]
}
```

个人校准用于生成或调整份量模板，不直接做图像估算。

### Entry

```json
{
  "id": "entry_001",
  "timestamp": "2026-05-18T11:20:00+08:00",
  "items": [
    {
      "foodId": "food_rice",
      "portionId": "portion_rice_fist",
      "grams": 150,
      "nutrition": {
        "calories": 174,
        "protein": 3.9,
        "carbs": 38.85,
        "fat": 0.45
      }
    }
  ],
  "note": "",
  "photo": "optional-data-url"
}
```

一条记录可以包含一个或多个食物项。例如一次记录可以是“米饭 + 鸡胸肉”。

### WaterEntry

```json
{
  "id": "water_001",
  "timestamp": "2026-05-18T15:30:00+08:00",
  "milliliters": 300
}
```

### DailyGoal

```json
{
  "calories": 2000,
  "protein": 100,
  "waterMl": 2000
}
```

目标全部可选。不设置目标时，页面只显示累计值。

## 计算规则

常规食物：

```text
营养值 = 食物每 100g 营养值 * 估算克数 / 100
```

包装食品：

- 如果按每 100g 录入，仍使用克数比例计算。
- 如果按每包或每份录入，按份数比例计算。

汇总：

- 今日概览汇总当天所有 `Entry.items` 的营养值。
- 饮水汇总当天所有 `WaterEntry.milliliters`。
- 最近 7 天统计按本地日期聚合。

修正：

- 用户可在添加记录时手动改重量。
- 用户可编辑单条记录的重量和营养估算。
- 编辑后首页和统计重新计算。

显示口径：

- 热量单位：kcal。
- 蛋白质、碳水、脂肪单位：g。
- 饮水单位：ml 或 L。
- 页面显示“粗略估算”提示。

## 添加记录流程

1. 用户在首页横向快捷区点击常吃食物，或进入搜索/更多。
2. 弹出添加记录面板。
3. 用户选择份量，例如 `半拳`、`1拳`、`1.5拳`、`自定义克数`。
4. 用户可添加多个食物项。
5. 用户可添加备注和照片。
6. 用户保存。
7. 新记录进入今日时间线，今日概览同步更新。

## 图片策略

- 食物库图片用于识别常吃食物卡片，提升界面辨识度。
- 记录照片用于回忆当天吃了什么。
- 照片不参与算法识别、估重或营养计算。
- 首版照片通过浏览器文件输入添加。
- 首版可用 data URL 存储照片；若出现容量问题，后续迁移到 `IndexedDB`。

## 视觉方向

界面应偏生活化和轻量，而不是医疗或健身房风格。

- 适合 iPhone 单手操作。
- 保持足够信息密度，避免营销式首页。
- 使用食物缩略图、记录照片和温暖但克制的色彩。
- 卡片圆角控制在 8px 左右，整机 mockup 不影响实际 UI。
- 关键按钮应足够大，适合触控。

## 错误与空状态

- 无食物时：首页快捷区展示“添加第一个常吃食物”。
- 无记录时：今日时间线展示空状态和添加入口。
- 营养字段缺失时：保存食物前提示补全；用户可保存为“仅记录不计算”。
- 图片过大时：提示用户压缩或改用无图记录。
- localStorage 不可用时：显示无法保存数据的提示。

## 验证范围

手动验证：

- iPhone 窄屏布局不溢出。
- 横向快捷添加区可左右滑动。
- 今日时间线可上下滚动。
- 新增食物后出现在食物库和快捷区。
- 添加记录后今日概览更新。
- 添加饮水后饮水汇总更新。
- 刷新页面后本地数据保留。
- 附照片的记录能展示缩略图。
- 无照片记录正常展示。
- PWA manifest 可加载，图标可用。

代码验证：

- 营养计算函数覆盖常规食物和包装食品。
- 日期聚合函数覆盖最近 7 天统计。
- 数据导入导出能保留食物、份量、记录、设置。
