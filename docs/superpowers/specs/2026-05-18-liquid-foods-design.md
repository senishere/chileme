# 液体单位与内置食物库设计

日期：2026-05-18

## 目标

升级“吃了么”的食物数据和记录模型，使它支持液体食物的 `ml` 单位、钠含量，并提供一批混合版常见食物，减少用户首次使用时的手动录入。

## 范围

包含：

- 份量支持 `g` 和 `ml`。
- 新增 `per100ml` 营养标注方式。
- 营养字段新增 `sodium`，单位 `mg`。
- 液体食物支持 `densityGPerMl`，默认 `1`。
- 内置约 60 个混合版常见食物：中式日常、健身轻食、饮品、零食、包装/高钠项。
- 旧数据升级：旧营养补 `sodium: 0`，旧份量补 `unit: "g"`。
- 自动补充缺失的内置食物，不覆盖用户已有同 id 食物。

不包含：

- 医疗级营养数据库。
- 条码扫描。
- 拍照识别。
- 云端同步。

## 数据规则

`Food.nutrition` 扩展为：

```json
{
  "calories": 116,
  "protein": 2.6,
  "carbs": 25.9,
  "fat": 0.3,
  "sodium": 1
}
```

`Food.nutritionMode` 支持：

- `per100g`
- `per100ml`
- `perServing`
- `perPackage`

`Portion` 扩展：

```json
{
  "id": "portion_milk_cup",
  "foodId": "food_milk",
  "label": "1杯",
  "amount": 250,
  "unit": "ml",
  "grams": 250
}
```

兼容规则：

- 旧 `portion.grams` 继续可读。
- 新代码优先使用 `amount` + `unit`。
- 旧记录 item 没有 `unit` 时默认 `g`。
- 液体显示 `ml`，固体显示 `g`。

## 内置食物库

内置库作为默认数据源和升级补充源。用户已有同 id 食物时，不覆盖用户数据。

营养数值使用常见平均值，只用于粗略估算。钠单位为 mg。

## UI 规则

- 添加食物表单支持选择默认份量单位 `g/ml`。
- 营养标注方式支持 `每 100g`、`每 100ml`、`每份`、`整包`。
- 记录弹窗份量显示对应单位。
- 今日记录和食物库显示钠信息，但首页摘要保持简洁。
- 统计页增加钠汇总。

## 验证

- `per100ml` 和 `sodium` 计算有单元测试。
- 旧数据升级有单元测试。
- 内置食物补充不覆盖用户数据有单元测试。
- 浏览器手动验证液体饮品可按 ml 记录。
