# 单位简化与食物体验改造设计

日期：2026-05-18

## 目标

把“吃了么”的记录和食物管理体验从份量模板驱动改为重量/体积驱动。用户记录食物时只需要选择食物并输入 `g` 或 `ml`，不再面对拳、碗、根、把、每份、整包、密度等概念。

本次改造优先服务日常快速记录和直观复盘，不追求医学级精度。所有营养结果继续作为粗略估算展示。

## 核心决定

- 采用彻底迁移，不保留份量模板作为新模型的一部分。
- 食物营养统一为每 `100g`。
- 记录时食物默认输入 `g`，饮品可输入 `ml`；`ml` 按 `1ml = 1g` 粗略换算。
- 删除用户界面中的拳、掌心、手指、碗、杯、勺、根、个、把、份、每份、整包和液体密度配置。
- 今日记录条目不显示钠，只保留食物、数量、热量、备注和照片等记录信息。
- “食物库”改名为“食物”。
- 分类可新增、重命名、删除。
- 统计页只展示趋势，不堆叠每日详细数字。

## 数据模型

### Food

食物保留用户可理解的基础字段：

```json
{
  "id": "food_rice",
  "name": "米饭",
  "category": "细粮",
  "icon": "🍚",
  "image": "",
  "nutritionPer100g": {
    "calories": 116,
    "protein": 2.6,
    "carbs": 25.9,
    "fat": 0.3,
    "sodium": 1
  },
  "quickAdd": true
}
```

不再新建或编辑：

- `nutritionMode`
- `densityGPerMl`
- `servingGrams`
- `packageGrams`
- `defaultPortionId`
- `Portion`

### Entry Item

每条记录项只保存本次实际输入的数量和单位：

```json
{
  "foodId": "food_rice",
  "amount": 150,
  "unit": "g",
  "grams": 150,
  "nutrition": {
    "calories": 174,
    "protein": 3.9,
    "carbs": 38.85,
    "fat": 0.45,
    "sodium": 1.5
  }
}
```

`unit` 仅支持：

- `g`
- `ml`

当 `unit` 为 `ml` 时，`grams = amount`。

### Category

分类从隐式字符串升级为用户可管理的数据：

```json
{
  "id": "category_fine_grain",
  "name": "细粮",
  "icon": "🍚"
}
```

默认分类：

- 细粮
- 粗粮
- 动物蛋白
- 植物蛋白
- 蔬菜
- 水果
- 奶
- 饮料
- 坚果
- 零食
- 餐食
- 其他

删除分类时，已有食物迁移到“其他”。重命名分类时，已有食物随分类显示新名称。

## 图标

新增/编辑食物时允许用户选择图标。分类提供默认图标和候选图标。

建议候选：

- 细粮：🍚、🍜、🍞
- 粗粮：🌾、🍠、🌽、🥔
- 动物蛋白：🥩、🍗、🐟、🥚、🦐
- 植物蛋白：🫘、⬜、🥜
- 蔬菜：🥬、🥦、🍅、🥒、🥕、🍄
- 水果：🍎、🍌、🍊、🍓、🍇、🫐
- 奶：🥛、🧀、🍦
- 饮料：🥤、☕、🧃
- 坚果：🥜、🌰
- 零食：🍪、🍫、🍟
- 餐食：🍱、🥗、🍛、🥟、🍣
- 其他：🍽️

如果用户没有选择图标，则使用分类默认图标。

## 页面设计

### 今天

首页保持“概览 + 今日结构 + 快捷添加 + 今日记录”。

记录流程：

1. 点击快捷食物或自定义记录。
2. 选择食物。
3. 输入数量。
4. 选择单位 `g/ml`。
5. 可选备注和照片。

不再选择份量模板。

今日记录条目展示：

- 时间
- 食物名
- `150g` 或 `250ml`
- 约 `xxx kcal`
- 备注
- 照片

今日记录条目不显示钠。

### 今日结构

使用进度条，不使用饼图。

每项展示：

- 指标名称
- 完成比例
- 状态等级
- 进度条

不展示“缺多少 g”或“超多少 g”。

状态等级：

- `< 40%`：严重不足
- `40%-75%`：不足
- `75%-105%`：正常范围
- `105%-120%`：偏高
- `> 120%`：超量

钠是上限指标，不显示“不足”。钠状态：

- `<= 100%`：正常范围
- `100%-120%`：偏高
- `> 120%`：超量

饮水可使用同一套比例状态，但文案保持轻量，不做健康诊断。

### 食物

底部导航从“食物库”改为“食物”。

食物页包含：

- 搜索。
- 分类筛选。
- 分类管理入口。
- 食物列表。
- 新增食物入口。

食物行展示：

- 图标或图片。
- 名称。
- 分类。
- 每 `100g` 热量摘要。
- 常用标记。
- 编辑入口。

新增/编辑食物页字段：

- 名称。
- 分类。
- 图标。
- 图片。
- 每 `100g` 热量。
- 每 `100g` 蛋白质。
- 每 `100g` 碳水。
- 每 `100g` 脂肪。
- 每 `100g` 钠。
- 是否常用。

不再出现：

- 类型：常规食物/包装食品。
- 营养标注方式。
- 默认份量名称。
- 默认份量数量。
- 默认份量单位。
- 液体密度。
- 每份重量/容量。
- 整包重量/容量。

### 分类管理

分类管理可以作为食物页内的弹窗。

支持：

- 新增分类。
- 重命名分类。
- 删除分类。
- 选择分类默认图标。

基础规则：

- “其他”不可删除。
- 删除非空分类时，分类下食物迁移到“其他”。
- 分类名称不能为空。
- 分类名称不能重复。

### 统计

统计页分两个 tab：

- 最近一周。
- 最近一月。

统计页只展示趋势和少量摘要，不展示每天的大量数字。

建议展示：

- 热量趋势。
- 记录次数趋势。
- 饮水趋势。
- 可选：蛋白质趋势。

每天的详细数值不在主界面平铺；需要更细数据时通过导出 CSV/JSON 查看。

### 设置

设置页保留：

- 个人资料：性别、年龄、身高、体重、活动水平、目标。
- 每日目标：热量、蛋白质、饮水。
- 数据管理：导出、导入、清空。

移除：

- 拳头宽度。
- 掌心宽度。
- 手指宽度。
- 常用容器名称。
- 常用容器容量。

## 迁移规则

因为当前项目还没有真实用户输入数据，本次可以做破坏性简化，但仍应保证旧本地状态不会导致页面崩溃。

迁移策略：

- 旧 `foods` 转换为新 `foods`。
- 旧 `nutrition` 转换为 `nutritionPer100g`。
- 旧 `per100ml` 直接按每 `100g` 使用。
- 旧 `perServing` 和 `perPackage` 的内置食物改为合理的每 `100g` 默认值。
- 旧 `portions` 不再保留。
- 旧记录项保留 `amount/unit/grams/nutrition`；缺失 `amount` 时用旧 `grams`。
- 旧分类字符串映射到新分类；无法识别时归为“其他”。
- 旧校准字段丢弃。

## 测试

需要覆盖：

- 每 `100g` 营养计算。
- `ml` 按 `1ml = 1g` 换算。
- 旧状态迁移到新模型。
- 分类新增、重命名、删除规则。
- 删除分类后食物迁移到“其他”。
- 今日记录不渲染钠。
- 食物编辑页不包含旧份量/包装字段。
- 统计页周/月 tab。
- 设置页不包含旧校准字段。

## 非目标

- 不做医学建议。
- 不接入大型食物数据库。
- 不做条码扫描。
- 不做拍照识别。
- 不保留拳、碗、份等估算输入。
