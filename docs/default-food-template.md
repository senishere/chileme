# 默认食物数据模板

这个文件用于手动维护默认分类、默认 emoji 和默认食物数据。实际 App 读取的默认数据仍在 `src/domain.js`，修改后需要把这里整理好的条目同步到 `src/domain.js`。

## 修改位置

默认分类和 emoji 候选：

```text
src/domain.js
const ICON_OPTION_VALUES = { ... }
```

默认食物：

```text
src/domain.js
const DEFAULT_FOODS = [ ... ]
```

## 分类模板

分类名必须和食物条目里的分类完全一致。每个分类数组里的第一个 emoji 会作为分类默认图标。

```js
const ICON_OPTION_VALUES = {
  "细粮": ["🍚", "🍜", "🍞"],
  "粗粮": ["🌾", "🍠", "🌽", "🥔"],
  "动物蛋白": ["🥩", "🍗", "🐟", "🥚", "🦐"],
  "植物蛋白": ["🫘", "⬜", "🥜"],
  "蔬菜": ["🥬", "🥦", "🍅", "🥒", "🥕", "🍄"],
  "水果": ["🍎", "🍌", "🍊", "🍓", "🍇", "🫐"],
  "奶": ["🥛", "🧀", "🍦"],
  "水": ["💧", "🚰"],
  "饮料": ["🥤", "☕", "🧃"],
  "坚果": ["🥜", "🌰"],
  "零食": ["🍪", "🍫", "🍟"],
  "餐食": ["🍱", "🥗", "🍛", "🥟", "🍣"],
  "其他": ["🍽️"]
};
```

新增分类示例：

```js
"豆制品": ["🫘", "⬜"],
"调味": ["🧂", "🍶"]
```

## 食物模板

每条默认食物使用 `food(...)`。营养值统一是每 `100g`。

```js
food("food_unique_id", "食物名", "分类名", "emoji", {
  calories: 100,
  protein: 1,
  carbs: 10,
  fat: 1,
  sodium: 0
})
```

字段单位：

- `calories`：kcal / 100g
- `protein`：g / 100g
- `carbs`：g / 100g
- `fat`：g / 100g
- `sodium`：mg / 100g

示例：

```js
food("food_kiwi", "猕猴桃", "水果", "🥝", {
  calories: 61,
  protein: 1.1,
  carbs: 14.7,
  fat: 0.5,
  sodium: 3
})
```

不默认放进快捷添加的示例：

```js
food("food_soy_sauce", "酱油", "调味", "🍶", {
  calories: 53,
  protein: 8,
  carbs: 4.9,
  fat: 0.6,
  sodium: 5600
}, false)
```

## 命名规则

- `id` 必须唯一。
- 建议使用 `food_英文名` 或 `food_拼音名`。
- 不要复用已有食物的 `id`，除非你明确想维护同一个默认食物。
- 分类名必须存在于 `ICON_OPTION_VALUES`，否则导入或加载时可能会归到“其他”。
- emoji 可以和分类默认 emoji 不同。

## 本地数据规则

默认数据只负责初始化和补充缺失食物。为了保护用户手动改过的数据，App 不会用默认库覆盖本地已有同 `id` 的食物。

这意味着：

- 新增默认食物：会补充进现有本地数据。
- 修改已有默认食物的分类、emoji 或营养：可能不会影响已经保存在浏览器里的同 `id` 食物。
- 想测试全新默认库：先在设置页导出完整备份 JSON，再清空本地数据重新打开。

## 修改后检查

修改 `src/domain.js` 后至少运行：

```bash
npm test
node --check src/domain.js
```

如果改了分类迁移或默认食物合并逻辑，也运行：

```bash
node --test tests/store.test.mjs
```
